# Ratatui App - Module Browser

## Overview

A terminal UI that lists the learning modules in `src/` and runs them.
Modules register themselves; the dashboard never names a module explicitly.
Files below are ordered as they come into play: compile, link, then runtime.

- Started from `src/main.rs` with `common::ratatui_app::index(true)`.
- Only modules that call `crate::tui_module!` appear in the TUI.
- Sections of a module are discovered from its files, not listed by hand.

## Registering a Module

The only code a module needs to appear in the TUI.
It goes in the module's own `mod.rs`, e.g. `src/basics/mod.rs`.

```rust
crate::tui_module! {
    description: "Fundamental Rust concepts and syntax",
    category: Basics,
}
```

- `description`: text shown in the details panel.
- `category`: one of `Basics`, `Intermediate`, `Advanced`, `Concurrency`,
  `DataStructures`, `System`.
- The module name is taken from `module_path!()`, e.g. `basics`.
- A section is any `pub mod <name>;` whose file has
  `pub fn index(show: bool) {`.
- Section labels come from file names: `if_let.rs` becomes `If Let`.
- A module without sections runs its own `index(true)` on Enter.
- Deleting a module: remove its directory, its `pub mod` in `src/lib.rs`
  and its line in `src/main.rs`. Nothing changes in `src/ratatui_app/`.

## 1. build.rs (compile time)

Lives at the repository root and runs before the crate is compiled.
Discovers the sections of every registered module.

- Scans every `src/<module>/mod.rs`.
- Keeps only modules whose `mod.rs` contains `crate::tui_module!`.
- For each `pub mod <name>;`, reads `<name>.rs` or `<name>/mod.rs`.
- Keeps files with the exact line `pub fn index(show: bool) {`.
- Other signatures (e.g. returning `Result`) are skipped, not errors.
- Writes one file: `$OUT_DIR/tui_sections.rs`, a `sections(module)` match.
- `cargo:rerun-if-changed=src` regenerates it when any file in `src/` changes.

## 2. registry.rs (link time)

Defines what a module is and collects every registration.
Uses the `inventory` crate, so registrations need no central list.

- `Category`: module group, with `label()` for display.
- `Section`: `name`, `description` and `run: fn()` of one child module.
- `TuiModule`: `path`, `description`, `category` and `run: Option<fn()>`
  (`None` for modules registered with `sections_only`).
- `TuiModule::name()`: last segment of `path`, e.g. `common::basics` → `basics`.
- `TuiModule::sections()`: looks up the sections generated by `build.rs`.
- `modules()`: every registered `TuiModule`, sorted by name.
- `tui_module!`: wraps `inventory::submit!` to build a `TuiModule`.
- Test: `arrays` is registered with its three discovered sections.

## 3. mod.rs (entry point)

Public face of the TUI, following the repository's `index(show)` pattern.
Declares the private submodules and re-exports the registry types.

- `index(true)` starts the dashboard; `index(false)` does nothing.
- Re-exports `Category`, `Section` and `TuiModule` for `tui_module!`.
- Errors from the terminal are printed to stderr.

## 4. dashboard.rs (event loop)

Owns the terminal and the main loop; holds no state and no module names.
Kept deliberately small.

- `run_app()`: `ratatui::run` sets up and restores the terminal,
  including on panic.
- `event_loop()`: draw, wait for a key press, hand it to `App::on_key`.
- The loop ends when `App::should_quit` is set.

## 5. app.rs (state and behavior)

All dashboard state and what each key does.
Rendering lives in `ui.rs`; this file never draws.

- `App`: registered modules, list selections, scrollbar and last output.
- `Output`: captured text plus the module or section that produced it.
- `Focus`: which panel receives `↑`/`↓`.
- `on_key()`: maps keys to actions (see Keys below).
- `select_module()`: selects a module, its first section, clears output.
- `run_selected()`: runs the selected section, or the module itself.
- `wrap()`: moves a selection by ±1, wrapping at both ends.
- `capture_stdout()`: runs a `fn()` and returns what it printed,
  using `gag::BufferRedirect`.

## 6. ui.rs (rendering)

Draws `App` state with ratatui widgets.
Only reads navigation state; never changes what is selected.

- `draw()`: header, module list (40%), details (60%) and footer.
- `render_module_list()`: numbered module list with a scrollbar.
- `render_sections()`: section list on top, details or output below.
- `render_module_details()`: module summary, or its output once run.
- `render_footer()`: key hints for the current mode.
- Helpers: `panel()`, `numbered()`, `bold()`, `category_color()`.
- Test: renders to a `TestBackend` and checks the `basics` sections.
- `app.rs` tests: panel cycling in both directions and per-panel movement.

## Keys

Handled in `App::on_key()`.
Three panels, cycled like a circle: modules (left), submodules
(right-top) and output (right-bottom). The focused panel has a green border.
Modules without submodules have only two panels: modules and details.

- `Tab`/`→`/`l`: next panel (modules → submodules → output → modules).
- `Shift+Tab`/`←`/`h`: previous panel (modules → output → submodules → modules).
- `↑`/`k`, `↓`/`j`: move in the focused panel; scroll it in the output.
- `Home`, `End`: top/bottom of the focused panel.
- `Enter`: run the selected section or module.
- `c`/`Backspace`: clear the output.
- `q`/`Esc`: quit.

## Testing

Unit tests run without a real terminal.

- `cargo test --lib ratatui_app` runs the registry and rendering tests.
- Running sections is not unit-tested: the test harness captures stdout,
  so `capture_stdout()` sees nothing. Check it in the real TUI.
